# 폐쇄망 반입 무결성 절차 (M9)

작성 2026-09-07 · 개선계획 1단계 배포 위생 **M9** · 근거 기술검토 P1-13

폐쇄망으로 들여오는 산출물(코드·휠하우스·참조 데이터·모델 번들)에 대해 **무결성
검증 절차가 정의돼 있지 않았다.** 보고서가 그 공백을 스스로 적었으나 WBS·리스크에
연결되지 않았다. 이 문서가 절차이고, 도구는 `scripts/ops/intake_manifest.py` 다.

---

## 0. 이 절차가 막는 것과 막지 못하는 것

**막는 것** — 매체 복사 중 손상, 부분 반입, 누락, 반입 후 의도치 않은 변경,
반입 절차에 없던 파일의 혼입.

**막지 못하는 것** — **원본 자체가 이미 오염된 경우.** 그리고 **매니페스트가
대상과 같은 매체에 실려 온 경우의 위조.** 매체를 바꿀 수 있는 사람은 매니페스트도
함께 바꾼다.

그래서 §2 의 **자기 해시 대조**가 절차의 핵심이다. 그 단계를 건너뛰면 이 검증은
"매체 안에서 자기 자신과 일치한다" 는 것만 말하며, 그것은 무결성 검증이 아니다.

**서명 체계가 아니다.** 서명·인증서·타임스탬프는 범위 밖이며 필요하면 별도 결정이다.

---

## 1. 원본 쪽 — 매니페스트 생성

반입 폴더를 **매체에 담기 전에** 원본 환경에서 만든다.

```bash
python scripts/ops/intake_manifest.py generate <반입폴더> \
    --out <반입폴더>/MANIFEST.json \
    --intake-id <반입 건 식별자> --target-platform "Windows / Python 3.12"
```

**매니페스트를 반입 폴더 안에 두는 것이 전제다.** 도구는 매니페스트 자신을 목록에서
제외하므로 폴더 안에서 다시 만들어도 결과가 흔들리지 않는다.

출력에 **매니페스트 자기 해시**가 찍힌다. 그 값을 적어 둔다.

파일 이름·크기·SHA-256 만 담기며 파일 내용은 담기지 않는다 — 매니페스트는 매체에
함께 실려 다니고 사람이 눈으로 읽는다. 머리말에는 반입 건 식별자·대상 플랫폼·생성
시각·**검증기 코드 해시**가 들어간다. 검증기 코드 해시는 **출처 추적용이며 진본성을
보장하지 않는다** — 같은 매체로 온 검증기라면 그 값도 함께 바뀔 수 있다.

---

## 2. 자기 해시를 **다른 경로로** 전달한다

> **이 단계를 건너뛰면 나머지 절차가 무의미하다.**

매체가 아닌 경로로 전달한다 — 전화 구두 확인, 사내 메신저, 별도 인쇄물, 반입
신청서 기재 중 무엇이든 **매체와 다른 것**이면 된다.

반입 담당자는 그 값을 §3 의 출력과 대조한다. 다르면 **거기서 멈춘다.**

---

## 3. 반입 쪽 — 대조

설치 전에 돌린다. **venv 는 필요 없으나 Python 3.12 자체는 필요하다** — 반입 PC 에
신뢰할 수 있는 Python 이 어떻게 들어와 있는지는 이 절차의 **선행 조건**이며 여기서
다루지 않는다. 검증기가 **반입본 안에 있다면** 매니페스트에 포함되어 §2 대조로 함께 확인된다 —
반입본 밖에서 따로 들여오는 경우 그 검증기의 출처는 **이 절차가 보증하지 않는다.**

```bat
python scripts\ops\intake_manifest.py verify <반입폴더> --manifest <반입폴더>\MANIFEST.json
```

| 종료 코드 | 의미 | 조치 |
|---|---|---|
| **0** | 전량 일치 | §2 자기 해시가 맞았는지 확인한 뒤 설치 진행 |
| **2** | **검증 불가** — 매니페스트 없음·손상 | **이상 없음이 아니다.** 반입 절차를 다시 밟는다 |
| **3** | 변조·누락·**읽기 실패** | **반입본을 쓰지 않는다.** 원본 쪽에 통보. 읽기 실패는 파일 잠금·권한일 수 있으니 원인을 확인하되 **통과로 처리하지 않는다** |
| **4** | 목록 외 파일 | 그 파일이 왜 있는지 확인. 반입 절차 누락일 수 있다 |

**0 이 아닌 채로 설치하지 않는다.** 특히 2 를 "매니페스트를 안 만들었나 보다" 로
넘기지 않는다 — 그것이 이 절차가 존재하는 이유다.

검증 결과를 남길 때 **검증기 코드 해시·Python 버전·매니페스트 해시·담당자·시각**을
함께 적는다. 도구가 앞의 셋을 화면에 찍는다.

### 경로·파일 취급

- 경로에 공백이 있으면 **따옴표로 감싼다**
- **심볼릭 링크·정션은 이 도구가 대상으로 삼지 않는다.** 반입본에 그런 항목이
  있다면 절차를 다시 설계해야 한다
- 파일이 잠겨 있으면 읽기 실패로 잡힌다. 백신·인덱서가 잡고 있는 경우가 흔하다

---

## 4. 설치와의 순서

```
반입 매체 연결
  → 3. 대조 (0 확인)
  → 2. 자기 해시 대조 (다른 경로 값과 일치 확인)
  → **검증한 그 폴더를 그대로** install_312.bat
```

**설치 스크립트는 이 검증을 자동으로 호출하지 않는다.** 다만 **자동 결합이 본질적으로
위험한 것은 아니다** — 실패 시 설치를 차단하는 결합은 오히려 누락을 줄인다. 수동으로
두는 대신 아래 통제가 필요하다.

- 검증 결과를 **기록으로 남긴다**(§3). 구두 확인만으로는 나중에 무엇을 검증했는지 모른다
- **검증한 그 반입본을 그대로 설치한다.** 검증 이후 폴더를 교체·추가·수정하면 검증은
  무효다. 중간에 파일을 하나라도 바꿨다면 §3 을 다시 돌린다
- 검증과 설치 사이가 길어지면 다시 돌린다

이 통제를 지킬 자신이 없으면 **자동 결합(검증 실패 시 설치 차단)이 더 낫다.**
지금 수동으로 둔 것은 절차 도입 시점의 선택이며, 운영에서 재검토할 수 있다.

---

## 5. 무엇이 아직 닫히지 않았는가

| 항목 | 상태 |
|---|---|
| 절차·도구 | **초안 산출** — 실제 폐쇄망 반입으로 절차를 완주해 본 적은 없다 |
| 신뢰된 Python·검증기 확보 | **선행 조건이며 이 절차 밖** |
| 검증 이후 설치까지의 변경 통제 | 기록·동일본 설치로 규정했으나 **강제 장치는 없다** |
| **리스크 레지스터 등재** | **미완** — P1-13 은 "공급망 무결성" 을 리스크로 올릴 것을 함께 요구한다. 기존 리스크 항목은 패키지 누락·GPU 제약만 다룬다 |
| 원본 오염 대응 | 범위 밖 — 이 절차는 전송 구간만 본다 |
| 서명·인증서 | 범위 밖 |

**따라서 M9 는 P1-13 을 절반도 아직 닫지 않는다.** 도구와 절차는 나왔으나 **실제
반입으로 완주 검증을 하지 않았다.** 완주 후에 절차 부분을 종결하고, 리스크 레지스터
등재를 별도로 남기는 것이 순서다.
